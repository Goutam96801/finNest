# Expo Go + EAS Update CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Free, fully automated pipeline where every `git push` to the `prod` branch publishes a new over-the-air (OTA) JS update that anyone can open instantly in the **Expo Go** app (no App Store / Play Store step, no paid plan) — plus an optional, manually-triggered path to build a real installable Android APK later using the same free EAS tier.

**Architecture:** GitHub Actions watches the `prod` branch. On push, it installs deps, runs quality gates (lint, type-check, `expo-doctor`), then runs `eas update` to publish the JS bundle to the `production` EAS Update branch/channel. `expo-updates` (bundled inside Expo Go itself) resolves that published bundle when a user opens the app's Expo Go link/QR code. A second, manually-triggered workflow can build a real `.apk` with EAS Build (Free plan: 15 Android builds/month) for people who don't want to use Expo Go.

**Tech Stack:** Expo SDK 54 (`expo` ~54.0.35, `expo-router` ~6.0.24), EAS CLI, EAS Update, EAS Build, EAS Environment Variables, GitHub Actions, Supabase (server-side secrets only).

## Global Constraints

- Project uses Continuous Native Generation (CNG) — `android/` and `ios/` are git-ignored and regenerated by `expo prebuild`/`expo run:*`. Never hand-edit files under those folders; all native config changes go through `app.json`.
- Only Expo Go-compatible libraries may be relied on for the Expo Go/OTA path (see [Determining third-party library compatibility](https://docs.expo.dev/workflow/using-libraries/#determining-third-party-library-compatibility)). Every dependency currently in `package.json` is Expo Go-compatible as of SDK 54.
- **Known limitation:** remote push notifications via `expo-notifications` do **not** work inside Expo Go on Android (removed since SDK 53) — only local/in-app notifications work there. Full push notification testing requires a development build or the production APK, not Expo Go.
- Never prefix a secret value with `EXPO_PUBLIC_`. Anything with that prefix is compiled in plain text into the JS bundle and is visible to every user — treat it as public. Today only `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_KEY` (the anon key, which is meant to be public and is protected by Supabase Row Level Security) qualify.
- `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`, `RAZORPAY_KEY_ID`, `RAZORPAY_PLAN_NEST_MONTHLY`, `RAZORPAY_PLAN_NEST_YEARLY`, and `SUPABASE_DB_PASSWORD` are currently sitting in the mobile app's `.env.local` but are **not referenced anywhere in the mobile app code** (confirmed: only `lib/supabase.ts` reads `process.env.EXPO_PUBLIC_*`). They belong to Supabase Edge Functions and must never enter the mobile bundle, EAS environment variables, or GitHub Actions secrets for this mobile repo's workflows.
- Secrets live in exactly one of three places — never copy a value into more than one:
  1. **EAS Environment Variables** — `EXPO_PUBLIC_*` values, scoped per environment (`development` / `preview` / `production`).
  2. **GitHub Actions repository secret** — exactly one, `EXPO_TOKEN` (the only credential CI needs).
  3. **Supabase Edge Function secrets** — Razorpay + DB password, server-side only.
- Git branch `prod` (already exists, currently checked out) is the single trigger for the automated production OTA publish. `master` and feature branches are not wired to auto-publish in this plan.
- EAS Free plan limits (expo.dev/pricing, checked 2026-08-04): 15 Android + 15 iOS builds/month, low-priority build queue, 1,000 monthly active users for Update, 100 GiB update bandwidth, 20 GiB update storage. GitHub Actions minutes are separate and come from GitHub's own free tier (2,000 min/month on private repos, unlimited on public repos) — this plan's OTA workflow does not consume any EAS build credit, only the manual APK workflow does.
- Existing project identifiers (do not change): EAS `projectId` = `bb5e0457-ec52-461c-a1da-4872a8ab30d1`, owner = `goutam96801`, slug = `finnest`. (Note: the original plan draft referenced a stale ID `6725c9f4-...` left over in `app.json` from before the project was recreated on expo.dev — it was inaccessible to this account and has been replaced via `eas init`.)

## Task 6: GitHub Actions workflow — auto-publish OTA update on push to `prod`

**Files:**
- Create: `.github/workflows/eas-update-prod.yml`

**Interfaces:**
- Consumes: `EXPO_TOKEN` secret (Task 5), `production` EAS environment (Task 3), `production` channel (Task 2).

- [ ] **Step 1: Create the workflow file**

```yaml
name: EAS Update (production)

on:
  push:
    branches:
      - prod

concurrency:
  group: eas-update-production
  cancel-in-progress: true

jobs:
  update:
    name: Publish EAS Update
    runs-on: ubuntu-latest
    steps:
      - name: Check for EXPO_TOKEN
        run: |
          if [ -z "${{ secrets.EXPO_TOKEN }}" ]; then
            echo "Missing EXPO_TOKEN secret. Add it under Settings > Secrets and variables > Actions."
            exit 1
          fi

      - name: Checkout repository
        uses: actions/checkout@v5

      - name: Setup Node
        uses: actions/setup-node@v6
        with:
          node-version: 20
          cache: npm

      - name: Setup EAS
        uses: expo/expo-github-action@v8
        with:
          eas-version: latest
          token: ${{ secrets.EXPO_TOKEN }}

      - name: Install dependencies
        run: npm ci

      - name: Lint
        run: npm run lint

      - name: Type-check
        run: npx tsc --noEmit

      - name: Validate Expo config
        run: npx expo-doctor

      - name: Publish update to production
        run: |
          npx eas-cli update \
            --branch production \
            --channel production \
            --environment production \
            --message "${{ github.event.head_commit.message }}" \
            --non-interactive
```

> Every step before "Publish update" is a quality gate: if lint, `tsc`, or `expo-doctor` fails, the job stops and no update is published — a broken commit on `prod` never reaches users.

- [ ] **Step 2: Commit and push to `prod` to trigger it for the first time**

```sh

git commit -m "ci: auto-publish EAS Update on push to prod"
git push origin prod
```

- [ ] **Step 3: Verify in GitHub**

Open `https://github.com/Goutam96801/finNest/actions`, confirm the "EAS Update (production)" run is green, and that the final step's log prints an update page URL like `https://expo.dev/accounts/goutam96801/projects/finnest/updates/<update-id>`.

## Task 7: (Optional) Manual GitHub Actions workflow for a real Android APK build

**Files:**
- Create: `.github/workflows/eas-build-prod.yml`

**Interfaces:**
- Consumes: `EXPO_TOKEN` secret (Task 5), `production` build profile from `eas.json` (Task 2).

This is deliberately **manual** (`workflow_dispatch`), not triggered on every push, to conserve the Free plan's 15 Android builds/month.

- [ ] **Step 1: Create the workflow file**

```yaml
name: EAS Build (manual)

on:
  workflow_dispatch:
    inputs:
      profile:
        description: "eas.json build profile"
        required: true
        default: "preview"
        type: choice
        options:
          - preview
          - production

jobs:
  build:
    name: Build Android with EAS
    runs-on: ubuntu-latest
    steps:
      - name: Check for EXPO_TOKEN
        run: |
          if [ -z "${{ secrets.EXPO_TOKEN }}" ]; then
            echo "Missing EXPO_TOKEN secret. Add it under Settings > Secrets and variables > Actions."
            exit 1
          fi

      - name: Checkout repository
        uses: actions/checkout@v5

      - name: Setup Node
        uses: actions/setup-node@v6
        with:
          node-version: 20
          cache: npm

      - name: Setup EAS
        uses: expo/expo-github-action@v8
        with:
          eas-version: latest
          token: ${{ secrets.EXPO_TOKEN }}

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npx eas-cli build --platform android --profile ${{ inputs.profile }} --non-interactive --wait
```

- [ ] **Step 2: Commit**


## Task 9: Rollback runbook (reference, no action needed now)

Keep this section for when a bad update ships:

```sh
# See what's currently live on the production channel
npx eas-cli@latest channel:view production

# Re-publish a previous, known-good update group on top of the bad one
npx eas-cli@latest update:republish --channel production --group <good-update-group-id>
```

`update:republish` works like `git revert` — it creates a new update pointing at old content, so every user's next app open/reload gets the good version again without needing a new build.
